## 1. 가장 먼저 알아야 할 현재 방향

MEKIT은 Modern Craft 액세서리 브랜드다. 첫 제품은 **001 EARTH**, 소비자가는 **49,000원(VAT 포함)**이다. 제품 기준은 사용자가 선택한 원본 EARTH 디자인 보드, 패키징은 재생용지 기반 MATERIAL WRAP이다.

고객은 브랜드가 완성한 팔찌 디자인과 길이를 선택한다. 첫 구매에서 비즈·소재·매듭을 직접 조립하거나 구성하도록 요구하지 않는다. 카메라로 손목을 비추면 선택한 팔찌의 착용 모습을 보는 AR 경험을 개발한다.

앱인토스를 초기 판매 채널로 검토했지만, 그 제약에 맞추기 위해 원하는 AR 경험을 포기할 필요는 없다. 사용자가 독립 네이티브 앱 대안을 제안했고 **“아이폰에서 해보자”**고 결정했다. **다음 개발 작업은 EARTH 한 모델의 독립 iPhone 착용 미리보기 프로토타입**이다.

기존 웹 커머스 데모는 GitHub에 존재한다. **이번 브랜드/AR 세션에서는 iOS 앱 소스·Xcode 프로젝트·실제 제품 3D 모델을 아직 만들지 않았다.** 기존 웹앱도 실제 결제·배송을 연결한 판매 서비스로 간주하지 않는다.

## 4. 001 EARTH 제품 디자인

**최우선 제품 기준:** 사용자가 선택한 `MEKIT 어스 브레이슬릿 디자인 보드.png`. 패키징 보드의 더 촘촘한 비즈 배열이나 이번 생성 시안으로 원본 기준을 대체하지 않는다.

- 슬림한 딥 올리브 코드가 중요한 시각 요소다.
- 작은 우드·천연석 비즈를 팔찌 둘레에 여백을 두고 분산한다.
- 황동 스페이서는 작고 절제되게 사용한다.
- 한국 전통매듭에서 영감을 받은 compact한 매듭과 브러시드 실버 원통 잠금장치를 조합한다.
- 심플하고 남성적인 Workwear 감성을 유지하되 지나치게 투박하거나 장식적으로 만들지 않는다.
- 빽빽한 비즈, 두 개 정도만 남긴 극단적 미니멀화, 한쪽으로 몰린 배열을 피한다.
- 마지막 제품 피드백은 **“팔찌가 너무 짧아 보여.”** 충분한 여유와 자연스러운 코드 구간을 실물로 검토해야 한다.

### 이번 세션의 FIT STUDY 01

원본 제품 보드와 최신 포장 보드를 참고해 이미지 생성 도구로 검토용 보드를 만들었다. 제품 전체, 위에서 본 배열, Workwear 착용 컷, 종이 포장을 함께 표현했다. 착용 컷의 여유를 수정하고 생성 과정의 중복 잠금장치를 한 개로 바로잡았다.

파일은 `assets/concepts/earth-fit-study-01.png`, 사용 프롬프트는 `docs/earth-fit-study-prompts.txt`다. **사용자의 최종 승인을 받은 대체 디자인이 아니며**, 패널 간 정확한 부품 위치·치수를 보장하는 제작 도면도 아니다. 특히 실제 20–20.5cm 착용감이나 잠금 구조·재질을 증명하지 않는다.

## 5. 내구성과 잠금장치 개발

필수 요구는 한 손 조작, 충격·당김으로 쉽게 분리되지 않는 잠금, 반복 사용에도 견고한 코드·금속 연결이다. 땀·습기 내식성, 코드 마찰, 매듭 풀림, 비즈 파손, 편안함, 수선 가능성을 검토한다.

자력은 결합 위치를 안내하고 **체결 후 당김 하중은 기계식 잠금 구조가 담당**하도록 설계한다. 일반 자석 버클을 검증된 회전 잠금장치와 동일하게 취급하지 않는다. 코드 끝단도 접착제만으로 고정하는 구성을 최종 구조로 바로 채택하지 않는다.

## 7. MATERIAL WRAP 패키징

질감 있는 재생용지 랩핑, Warm Oatmeal/Natural Gray, 작은 MEKIT 텍스트, 종이 띠, 제품 고정 카드, Material Record, 소형 골판지 메일러를 기본으로 한다. 파우치는 선택품이며 기본 포함으로 간주하지 않는다.

개봉은 종이 띠 제거 → 종이 펼치기 → 고정 카드의 EARTH 확인 → 소재·제작·관리 기록 확인 순서다. Material Record에는 제품명·실제 소재·완성 길이·제작 정보·관리·수선 안내를 담는다. 견적과 배송 보호 실물 검증은 남아 있다.

## 8. 구매 경험과 iPhone AR

목표 구매 흐름은 **완성 디자인 목록 → 제품 상세 → 내 손목에 착용해 보기 → 후보 비교 → 길이 선택 → 주문/결제**다. 첫 기술 검증에는 EARTH 한 개만 포함하고, 복수 컬렉션 비교는 이후 확장한다.

첫 iPhone 프로토타입의 범위:

- 후면 카메라로 반대편 손과 손목을 함께 비추는 가이드.
- 손목 위치·방향 추적과 EARTH 3D 팔찌 표시.
- 위치·크기 보정, 손목 뒤로 돌아간 팔찌의 가림.
- 추적 손실·권한 거절·카메라 중단·앱 이탈 처리.
- 기본 동작에서 카메라 영상을 서버에 전송하거나 저장하지 않는 방향.

쇼핑·계정·결제·Android 동시 구현은 첫 검증 범위가 아니다. 카메라 합성은 스타일·색·대략적인 비율 확인을 목표로 하며, 정확한 손목 둘레·실제 조임·촉감을 보장하지 않는다. 길이 선택은 별도 실물 검증과 사이즈 안내로 유지한다.

SwiftUI·AVFoundation·Apple Vision 손 포즈를 우선 검토하고, 필요 시 MediaPipe를 비교한다. 3D 렌더러와 가림 방식은 작은 검증으로 선택한다. ARKit/ARCore 도입 자체를 완성된 팔찌 착용 기능으로 간주하지 않는다. 손 랜드마크만으로 정확한 손목 형상·둘레가 확보된다고 가정하지 않는다.

참고 자료: [Apple Vision 손 포즈](https://developer.apple.com/documentation/vision/detecting-hand-poses-with-vision), [MediaPipe iOS](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/ios), [MediaPipe 웹](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js).

앱인토스 공식 답변은 WebView 실시간 카메라 처리가 가능할 것으로 예상하고 정책 허용 여부는 별도 문의하도록 안내했다. 독립 iPhone 앱은 해당 호스트 제약에서 벗어나 직접 카메라·렌더링을 구성하는 대안이다. 독립 앱과 토스 내부 React Native 미니앱을 혼동하지 않는다. [앱인토스 공식 답변](https://techchat-apps-in-toss.toss.im/t/react-native-webview/4250)

## 9. GitHub 원격 코드 확인 결과 — 로컬 자료와 구분

원격 저장소: [casewingit/mekit](https://github.com/casewingit/mekit). 기존 자료: [설계 이슈 #1](https://github.com/casewingit/mekit/issues/1), [참고 이미지 댓글](https://github.com/casewingit/mekit/issues/1#issuecomment-6089609572), [기존 사업·미니앱 기획서](https://github.com/user-attachments/files/33243671/MEKIT_._App-in-Toss_.md).

2026-10-11 확인한 main 커밋은 [`468f6d7db63ac7bc48f0fca3e563b654a4245645`](https://github.com/casewingit/mekit/tree/468f6d7db63ac7bc48f0fca3e563b654a4245645)이다. 커밋 메시지는 `build: configure GitHub Pages publishing`. React·TypeScript·Vite 기반 웹 커머스 MVP와 테스트 코드가 있다. 원격 README는 홈·컬렉션·찜·제품 상세·SVG 미리보기·길이 선택·데모 주문·소재/고객지원 흐름을 설명한다. 이번 인수인계 작성에서는 코드를 읽었으며 원격 앱의 테스트를 다시 실행하지 않았다.

원격 README의 공개 데모 주소는 [casewingit.github.io/mekit](https://casewingit.github.io/mekit/)이다. 이번 작업에서 사이트 동작이나 배포 상태를 새로 검증한 것은 아니다. 실제 Toss 로그인·결제·서버 주문·제작·배송·환불은 연결되지 않았다고 README에 명시되어 있다.

**중요한 차이:**

| 원격 코드/기존 자료                                         | 최신 기준 및 후속 작업                                                                 |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `src/domain/catalog.ts` EARTH `price: 39000`                | **49,000원으로 갱신 필요**. 이번 작업에서 코드 수정은 하지 않음                        |
| EARTH `beadCount: 23` 및 SVG 표현                           | 원본의 여백 있는 분산 배열과 동일한 실물 모델로 간주하지 않음. 이후 디자인 정합성 확인 |
| `src/domain/sizing.ts` 길이 15–21cm, 0.5cm 단위·고정 여유값 | 데모 규칙. 실물 길이/내부 둘레와 착용 검증을 근거로 갱신                               |
| 기존 웹 미리보기                                            | 실시간 카메라 AR이 구현된 것으로 간주하지 않음                                         |
| 개발 폴더에는 브랜드 자료만 있음                            | 원격에는 별도 웹앱 코드가 있으므로 다른 Mac에서 먼저 clone해 확인                      |

이 문서와 이슈 등록은 문서화 작업이다. 원격 코드 수정·main push·배포는 수행하지 않는다. 최신 main은 다른 Mac에서 다시 확인해야 한다.

## 11. 다른 Mac에서 바로 이어갈 작업

1. 원격 저장소와 이 인수인계 자료를 각각 확보한다. 문서 ZIP을 기존 코드 위에 통째로 덮어쓰지 말고, 새 문서·이미지를 검토해 병합한다. ZIP의 루트 README는 브랜드 세션 자료 안내이며 원격 웹앱 README와 다르다.
2. 작업 폴더의 AGENTS.md 등 적용 지침, Git 상태, 최신 main을 확인한다. 기존 변경은 보존한다.
3. Xcode와 iOS SDK, 사용할 실제 아이폰, 기기 신뢰·개발자 모드·서명 환경을 확인한다. 계정·기기 인증은 사용자가 수행한다.
4. 기존 웹앱과 구분되는 iPhone 프로토타입 작업 위치를 정한다. 같은 저장소라면 예를 들어 `ios/`를 검토하되 프로젝트 구조와 지침을 먼저 확인한다.
5. 카메라 시작/종료와 손 추적부터 실제 아이폰에서 검증한다. 이후 검증용 EARTH 모델을 붙이고 좌표·스케일·가림을 확인한다.
6. 자동 검증은 좌표 변환·보정·추적 손실 등 계산/상태에 사용하고, 착용 현실감은 실기기 영상과 실물로 확인한다.
7. 단말·OS·SDK 버전, 조명·자세, 로딩·프레임 속도·추적 복구, 알려진 한계를 기록한다. 시뮬레이터 확인을 실기기 카메라 검증으로 표현하지 않는다.
8. 결과를 보고 다른 컬렉션·쇼핑 연결·Android 확장 범위를 결정한다.

제품 제작 트랙은 별도로 잠금장치 사양/견적 → 부품 호환성/기계식 고정 → 10개 시제품 비교 → 실제 BOM/패키징 견적 순서로 이어간다. 내구성이 미확정인 구조를 수량만 맞추려고 임의 대체하지 않는다.

## 12. 인수인계 후 첫 개발 이슈의 완료 조건

- [ ] 실제 아이폰에서 카메라 동의·시작·종료가 동작한다.
- [ ] 손·손목 가이드와 추적 성공/손실 상태가 구분된다.
- [ ] EARTH 한 개가 손목 이동을 따라가고 위치·크기를 보정할 수 있다.
- [ ] 허용 각도 범위를 정의하고 그 범위에서 손목 뒤 가림을 검증한다.
- [ ] 권한 거절·중단·화면 이탈을 처리한다.
- [ ] 검증용 모델과 실제 제품의 차이, 사이즈 추정 한계를 명시한다.
- [ ] 기본 동작에서 영상이 저장·서버 전송되지 않는지 확인한다.
- [ ] 빌드/자동 테스트 결과와 실기기 검증 결과를 분리해 기록한다.

이 체크리스트는 **아직 완료하지 않은 다음 작업**이다. 개발 기간·비용·최소 iOS 버전·지원 기기·최종 3D 자산 방식은 환경과 초기 측정을 보고 정한다.

## 13. 새 개발 대화에 붙여 넣을 요청

> MEKIT의 이전 결정을 이어서 iPhone AR 착용 미리보기 프로토타입을 구현해줘. 먼저 이 인수인계 이슈 전체와 첨부/전달 문서를 읽고, 원격 casewingit/mekit의 최신 코드·Git 상태·프로젝트 지침을 확인해줘. 브랜드는 Modern Craft, 첫 제품 001 EARTH, 최신 소비자가는 49,000원이다. 원격 데모의 EARTH 39,000원은 과거 값이다. 고객은 완성 디자인과 길이를 선택하며 직접 부품을 구성하지 않는다. 제품은 원본 EARTH 보드의 슬림 올리브 코드·여백을 둔 우드/천연석/황동·전통매듭·단일 원통 잠금장치 비율을 유지한다. 먼저 독립 iPhone 네이티브 앱에서 EARTH 한 모델의 후면 카메라·손목 추적·3D 합성·위치/크기 보정·손목 뒤 가림을 구현하고 실제 아이폰에서 검증해줘. 기존 웹 커머스 코드를 보존하고 별도 iOS 작업 위치를 정해줘. 현재 iOS 소스와 실제 제품 3D 모델은 아직 없다. 기존 결정은 다시 논의하지 말고, 추정 사양·검증용 모델·실제로 확인한 동작을 구분해줘.
